# adddel 契約

## 位置づけ

この文書は `docs/design.md` に基づき、adddel の外部仕様と実装時に守る条件を定める。
インタビューで確定した仕様を以下に記載する。

## 入力と引数

- 比較対象のファイルを2つ指定する。
- 第1のファイル引数を変更前、第2のファイル引数を変更後として扱う。
- Gitリポジトリ外のファイルも比較できる。
- ディレクトリ単位の比較には対応しない。
- 通常ファイルのみを対象とし、シンボリックリンクはリンク先の通常ファイルを比較する。
- リンク切れ、ディレクトリ、FIFO、デバイス、読み取り不可の入力はエラーとする。
- 同一ファイル指定を許可し、通常の入力検証を通過すれば追加・削除ともに `0` とする。
- 空ファイル、空白・タブ・改行・日本語を含むファイル名に対応する。
- 改行コード、末尾改行、文字コードの変換や補正は行わず、Gitの集計に従う。
- Gitの集計列が `-` の場合はエラーとし、同一内容のバイナリでGitの出力が空なら追加・削除ともに `0` とする。

| 呼び出し | 動作 |
| --- | --- |
| `adddel old.txt new.txt` | 通常モードで集計結果を出力する。 |
| `adddel -l old.txt new.txt` | ラベル付きで集計結果を出力する。 |
| `adddel --label old.txt new.txt` | ラベル付きで集計結果を出力する。 |
| `adddel -h` | ヘルプを表示する。 |
| `adddel --help` | ヘルプを表示する。 |
| `adddel --version` | 埋め込まれたバージョンを表示する。 |

ラベル付き出力の長いオプション名は `--label` とする。

### 解析規則

- ファイル引数はちょうど2つとする。
- オプションは最初のファイル引数より前のみ解析する。
- `--` でオプション解析を終了し、それ以降はファイル名として扱う。
- ハイフンで始まるファイル名は `--` の後に置くか、`./-old.txt` のように指定する。
- `-l` と `--label` の重複指定を許可する。
- 不明なオプション、および `-lh` や `-ll` のような短いオプションの結合は引数エラーとする。
- 最初のファイル引数または `--` より前に `-h` または `--help` があれば、他の引数の不備よりヘルプを優先する。
- ヘルプの場合はファイルやGitを検証せず、標準出力にヘルプを表示して `0` で終了する。
- `--version` は標準出力に `adddel VERSION` と末尾改行を出し、ファイルやGitを検証せず `0` で終了する。
- `--version` の短縮オプションは追加しない。
- オプション解析の範囲では、ヘルプ、バージョン表示、引数不備の順に優先する。
- 最初のファイル引数または `--` より後の `-h`、`--help`、`--version` はオプションとして扱わない。
- バージョンは生成時に埋め込み、実行時にGitから取得しない。
- `src/adddel` の直接実行では、バージョンとして `@VERSION@` を表示する。

`adddel --unknown --help` はヘルプ表示となる。
`adddel -- --help new.txt` は `--help` という名前のファイルを比較する。
`adddel old.txt new.txt --label` はファイル引数過多のエラーとなる。

## 集計アルゴリズムと不変条件

- Bashで実装する。
- 差分の集計には `git diff --no-index --numstat` を使用する。
- 差分アルゴリズムを `myers` に固定する。
- indent heuristic、外部diff、textconv、リネーム検出を無効にする。
- 上記の固定条件はユーザーのGit設定に優先させる。
- `.gitattributes` によるテキスト／バイナリ判定の影響は許容する。
- Gitのバージョンや残る設定・属性の影響を完全に排除することは保証しない。
- Gitの出力は `-z` のNUL区切り形式で取得し、ファイル名に含まれるタブや改行に影響されず解析する。
- `--numstat` の第1列を追加行数、第2列を削除行数として取得する。
- Gitの終了コード `0` で出力が空なら、追加・削除ともに `0` とする。
- 独立したバイナリ検査は追加せず、Gitの集計列が `-` なら入力エラーとする。
- 列不足や非負整数以外の集計値など、不正な集計出力は処理失敗とする。
- 入力検証と集計が完了してから結果を出力する。
- 既存行の変更は、削除と追加として数える。
- 空白や空行の変更も差分として扱う。
- 差分が存在しない場合は、追加行数と削除行数をともに `0` とする。
- Gitの終了コード `1` は差分の存在を表すため、正常として扱う。
- 差分の詳細は表示せず、集計結果のみを標準出力に出力する。

## 出力形式

### 通常モード

追加行数、タブ文字、削除行数の順に、2列を1行で出力する。
次の例の `\t` は実際のタブ文字を表す。

```text
12\t5
```

### ラベル付きモード

`-l` または `--label` を指定した場合、次の形式で集計結果を出力する。

```text
additions: 12, deletions: 5
```

通常モード・ラベル付きモードともに、末尾に改行を1つ付ける。

## エラー処理と終了コード

| 状態 | 終了コード |
| --- | --- |
| 集計成功、差分の有無は問わない | `0` |
| ヘルプ・バージョン表示 | `0` |
| 引数不正、不明なオプション | `2` |
| ファイル不存在、リンク切れ、通常ファイル以外、読み取り不可 | `2` |
| Gitの集計列が `-` となるバイナリ | `2` |
| Git未導入、Gitの異常終了、集計出力の形式不正 | `1` |

差分の存在そのものはエラーとみなさない。
エラー時は標準出力を空にし、標準エラー出力に `adddel: 理由` の形式で英語のメッセージを出す。

### エラーメッセージの文面案

| 原因 | メッセージ案 |
| --- | --- |
| ファイル引数の数が不正 | `adddel: expected exactly two file arguments` |
| 不明なオプション・短いオプションの結合 | `adddel: unknown option` |
| ファイル不存在・リンク切れ | `adddel: input file does not exist` |
| 通常ファイル以外 | `adddel: input is not a regular file` |
| 読み取り不可 | `adddel: input file is not readable` |
| 集計列が `-` | `adddel: cannot count lines for binary input` |
| Gitが利用できない | `adddel: git is not available` |
| Gitの異常終了 | `adddel: git diff failed` |
| 集計出力の形式不正 | `adddel: invalid git diff output` |

### ヘルプ本文案

```text
Usage: adddel [-l | --label] [--] OLD NEW
       adddel -h | --help
       adddel --version

Count added and deleted lines between two files.
OLD is the original file; NEW is the modified file.

Options (before file arguments only):
  -l, --label  Print labeled counts; may be repeated.
  -h, --help   Show help and exit successfully.
  --version    Show version and exit successfully.
  --           End option parsing.

Output: additions<TAB>deletions, followed by a newline.
With --label: additions: N, deletions: N

Exit codes:
  0  Success, including differences, help, or version.
  1  Git unavailable or processing failed.
  2  Invalid arguments or input files, including uncountable binary input.
```

## 互換性と対象外

macOS・Linux、Bash 3.2以上、Git 2系を対象とする。
Gitリポジトリの存在は要求しない。
次の機能には対応しない。

- 差分の詳細表示
- 変更ブロック数の集計
- 変更率の計算
- ディレクトリ単位の比較
- 空白・空行を無視するオプション
- JSON出力

## 実装・生成・テストの配置

- プログラムの原本は `src/adddel` に配置する。
- manページの原本はMarkdownの `src/adddel.1.md` に配置する。
- `make dist` で `dist/bin/adddel` と `dist/share/man/man1/adddel.1` を生成する。
- manページはPandocで変換する。
- 生成したプログラムには実行権限を付ける。
- `/dist/` はGit管理対象外とする。
- CLIテストは `tests/test_adddel.bats`、生成処理のテストは `tests/test_dist.bats` に配置する。
- `bats tests` で全テストを実行し、`make test` では先に配布物を生成してから全テストを実行する。

## 配布物のメタデータ

- 基準タグはHEADから到達可能な `v数字.数字.数字` 形式のタグからGit describeで選ぶ。
- 注釈付きタグと軽量タグの両方を対象とする。
- HEADが基準タグと一致し、追跡ファイルに変更がなければ、先頭の `v` を除いたバージョンを使う。
- HEADが基準タグから離れている場合、`0.1.0-gabc1234` のようにHEADの短縮コミットIDを付ける。
- 追跡ファイルにステージ済みまたは未ステージの変更があれば、タグ一致時もコミットIDを付け、さらに `-dirty` を付ける。
- 未追跡ファイルはdirty判定に含めない。
- 日付はHEADのコミッター日時をUTCの `YYYY-MM-DD` に変換する。
- バージョンと日付はプログラムのヘッダーコメントとmanページへ埋め込む。
- `make dist` の実行ごとにGit情報を再取得し、タグの追加や変更も反映する。
- 到達可能なバージョンタグがない場合、またはGit・Pandocが利用できない場合は非ゼロ終了する。
- 変換途中の失敗で既存の配布物を上書きしないよう、両ファイルの生成完了後に配置する。
- 生成済みプログラムのヘルプとバージョン表示には、Gitや元のリポジトリを必要としない。

## 必要なテスト

### 正常系

- 追加のみの入力で追加行数と削除行数が正しいこと。
- 削除のみの入力で追加行数と削除行数が正しいこと。
- 行の変更が削除と追加として集計されること。
- 差分のない入力で両方の集計値が `0` となること。
- 空白や空行の変更が集計されること。
- 通常モードの列順、タブ区切り、1行の出力が契約と一致すること。
- `-l` と `--label` の出力がラベル付きの形式と一致すること。
- Gitリポジトリ外のファイルを比較できること。

### 異常系

- 引数不正で非ゼロ終了し、標準エラー出力にメッセージを出力すること。
- 存在しないファイルで非ゼロ終了し、標準エラー出力にメッセージを出力すること。
- 読み取りに失敗した場合に非ゼロ終了し、標準エラー出力にメッセージを出力すること。
- Gitの集計列が `-` の場合、終了コード `2` となること。
- 同一内容のバイナリでGitの出力が空なら `0` / `0` を返すこと。
- 差分集計に失敗した場合に非ゼロ終了し、標準エラー出力にメッセージを出力すること。

### 境界値と回帰

- Gitが終了コード `1` を返す差分ありの入力でも、adddelは `0` で終了すること。
- 差分の詳細が標準出力に混入しないこと。
- 空同士、空から非空、非空から空の集計が正しいこと。
- 末尾改行やLF・CRLFの違いを補正せず、Gitに従って集計すること。
- 空白、タブ、改行、日本語、先頭ハイフンを含むパスを扱えること。
- オプションの位置制約、重複許可、結合拒否、不明なオプション、`--` を検証すること。
- ヘルプの優先範囲と、引数不正・ファイル不備・Git未導入に対する優先動作を検証すること。
- シンボリックリンクをたどり、リンク切れ・ディレクトリ・FIFO・デバイス・読み取り不可を拒否すること。
- Git未導入、異常終了、不正な集計出力で終了コード `1` となること。
- 引数と入力の不備では終了コード `2` となること。
- エラー時に標準出力が空で、英語の診断が標準エラー出力に出ること。
- 出力の末尾改行を検証すること。
- ユーザー設定にかかわらずmyersと各無効化条件が適用され、外部diff・textconvが実行されないこと。
- `.gitattributes` によるテキスト／バイナリ判定の影響を許容すること。
- macOS・LinuxとBash 3.2互換の実装で契約を満たすこと。

### バージョンと生成処理

- バージョン表示の文面、末尾改行、終了コード、優先順位、解析範囲を検証すること。
- 元プログラムの直接実行では `@VERSION@` を表示し、生成物では確定したバージョンを表示すること。
- 軽量タグ・注釈付きタグ、タグ以降のコミット、ステージ済み・未ステージの変更を検証すること。
- 無関係なタグ、不正な形式のタグ、HEADから到達できないタグを基準にしないこと。
- タグなしで非ゼロ終了し、新しい配布物を生成しないこと。
- 日付がコミット日時のUTC日付であり、プログラムとmanページで一致すること。
- 同じコミットで再生成でき、後から追加されたタグも反映すること。
- Pandocの未導入・変換失敗で非ゼロ終了し、既存の配布物を保持すること。
- Gitが利用できない環境でも、生成済みプログラムのヘルプとバージョン表示が動作すること。
